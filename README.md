同一个局域网里，每台电脑启动阳鸽，就能自动看见彼此：发消息、传文件、共享文件柜、协作任务，甚至来一局双人角斗场。全程不碰外网、不依赖服务器，数据只在内网里走。适合公司内网、隔离网、实验室这类不方便、或者根本不允许连外网的环境。

> **二开说明**：阳鸽是开源项目 [Teahouse（茶话间）](https://github.com/skyjt/teahouse) 的二次开发版本（GPL-3.0-only），仓库为 [YangZhongJia/YangGe](https://github.com/YangZhongJia/YangGe)。相对上游重做了品牌与界面，并新增 AI 分身 / 剪贴板 / 输入中提示 / AI 群总结 / 任务中心 / 双人角斗场 / ACP Agent 协作等能力。

## 为什么做这个

内网里传个文件、说句话，本该是小事，可挑来挑去没一个顺手的：

- **飞鸽** 这类好用的商业工具需要付费；
- **内网通** 仅提供 Windows 版本，统信 UOS 与 Mac 无法直接安装；
- **iptux** 虽跨平台但界面上手门槛偏高，日常办公使用不够直观。

干脆自己写一个：免费开源、纯内网直连、从 Windows 7 到国产统信 UOS 再到 macOS 全平台覆盖、打开就会用。这就是阳鸽。

## 功能总览

### 沟通与互动

- **零配置发现**：UDP 广播自动发现同网段在线同事，节点直连通信，无需服务器或手动输入 IP。
- **单聊与讨论组**：文本、图片、截图粘贴、Twemoji 表情、自定义表情；送达确认、离线暂存与上线补发、2 分钟内撤回、转发、引用回复、群内 @ 成员。
- **窗口震动**：私聊即时提醒，带发送与接收限流，避免连续打扰。
- **输入中提示**：单聊实时显示「对方正在输入…」。
- **跨机剪贴板**：一键把本机剪贴板文本发给对方，对方可直接粘贴。
- **纸飞机 / 墨弹**：右键对方头像即可互动；纸飞机先在空中绕一圈再飞向对方最新消息头像，墨弹落点绽开带飞溅与滴落的靛蓝墨迹。纯视觉效果，不限次数与间隔，不抢焦点；可在「设置 → 提醒」关闭动画。
- **双人角斗场**：PK 菜单发起邀请，双方各自选招，见下方玩法说明。

### 任务中心

- 按项目组织任务，支持开始日期、截止日期、说明与完成状态。
- 列表按截止日自动分组：已延期、今天、本周内、以后、无截止日期、已结束。
- 截止日当天 09:00 后聚合提醒「今天到期」；启动或跨天时聚合提醒已逾期任务；任务入口显示未完成角标。
- 任务可共享给内网同事：支持多选同事、离线排队、上线补发、撤销共享与投递状态展示。
- 共享任务在接收方只读展示，提醒按接收方本机时间计算。

### 文件、屏幕与图片

- **点对点文件传输**：TCP 直连跑满局域网带宽；单文件、多选文件、完整文件夹；断点续传、传输历史、24 小时领取时效。
- **共享文件柜**：发布本地文件夹，配置关闭 / 只读 / 读写权限与按联系人例外；浏览同事文件柜、分页、面包屑、多选下载、拖拽上传。
- **原生截图**：快捷键唤起，支持矩形、画笔、箭头、马赛克、单行文字、放大镜与取色；适配 Wayland / X11。
- **屏幕协助（只查看）**：私聊发起，对方同意并选屏；独立窗口支持自动与 3/5/10 帧。
- **大图浏览与离线 OCR**：平滑缩放、双击锚点、旋转、会话内连续切换；内置 PaddleOCR + onnxruntime-web，离线识别并在原图上划选复制。

### AI 与 Agent

- **AI 分身（可选，默认关闭）**：配置 OpenAI 兼容接口（内网 Ollama / vLLM 或云端 API），自动代回单聊与群 @ 消息，带防互撸护栏、冷却与串行队列。
- **AI 群总结（可选）**：群聊右键总结当天消息，仅本机弹窗展示，绝不发进群。
- **本机 Agent**：扫描 PATH 与常见安装目录，识别 ACP Agent；支持显示名、简介、角色提示词、模型与启用状态。
- **协作任务**：协调者拆解 1–5 步计划，用户确认后由团队在隔离 worktree 中实现与审查，最终 diff 经确认才应用；不自动 commit / merge / push。

### 基础能力

- **本地历史与全文检索**：SQLite WAL + FTS，全局搜索联系人、群聊与消息；单会话历史搜索；本地备份导出与换机迁移。
- **多语言**：简体中文 / English 即时切换，全窗口同步。
- **局域网自更新**：安装包自留成源，P2P 拉包后一键静默安装并重启，全程零服务器、零外网。
- **纯内网安全边界**：启动注入 `--no-proxy-server`；零外网请求、零统计上报、零第三方 CDN；渲染进程严格沙箱与上下文隔离；网络报文白名单校验。
- **锁屏与版本亮点**：可选 6 位数字锁屏密码，启动、最小化或从托盘恢复时显示粒子蒙面；升级后首次进入展示当前版本新增项与一句已知 BUG 优化。

## 双人角斗场

1. 打开与同事的私聊，点击输入框工具栏的 **PK** →「角斗场」。
2. 对方接受后，聊天区出现角斗场浮层，双方各 **100 HP**。
3. 每回合 **10 秒**，双方各自选择「普通攻击 / 防御 / 搞怪技能」，出招互不可见；双方都出招后立即结算，超时按防御兜底。
4. 共 **6 回合**：任一方 HP 归零即 KO；回合耗尽按剩余血量判定，相同则平局。
5. 正常分出胜负后，结果作为系统消息写入双方各自的聊天记录；对手离线、主动退出、拒绝或邀请超时都会显示具体原因，不会虚构胜负。

> 双方都需要 1.11.0 或更高版本。旧版本没有 `duel1` 能力位，入口会置灰，也不会收到未知报文。

## 任务中心

- 顶部「新建任务」按项目创建任务；左侧可切换全部 / 我的任务 / 共享给我，并管理项目。
- 日期筛选只保留一个「开始」和一个「截止」边界。
- 任务行右侧可直接「共享」，详情顶部常驻编辑 / 共享 / 删除。
- 共享面板会区分「通讯录还没有同事」与「同事版本不支持任务共享」，并展示每条共享的投递状态。
- 提醒与角标只统计未完成任务；共享接收方按自己的本地日期计算提醒。

## 安装

从 [Releases](https://github.com/YangZhongJia/YangGe/releases) 下载对应平台安装包。Windows 提供两种形态：

- **NSIS 安装包** `YangGe-<版本>-win-x64-setup.exe`：双击安装，支持自定义目录与桌面快捷方式；
- **便携版** `YangGe-<版本>-win-x64-portable.exe`：免安装单文件，直接运行。

自行构建：

```bash
git clone https://github.com/YangZhongJia/YangGe.git
cd YangGe
npm install
npm run dist:win   # 产物在 release/
```

> 首次运行若系统防火墙弹出放行提示，请允许通行（默认端口：UDP `17878` 与 TCP `17879`）。

## 使用

1. 同一局域网设备各自启动阳鸽，自动出现在左侧列表。
2. 点击联系人开始单聊，或点击加号新建讨论组；拖入文件 / 文件夹即可发送。
3. 「文件柜」页签浏览同事共享目录，或发布本机目录并分配权限。
4. **跨网段**：UDP 广播无法穿透路由时，在「设置 → 网络」手动添加对端 IP 或 CIDR 网段；已保存网段会在在线节点间低频共享；导航栏刷新按钮可全局扫描并显示进度。
5. **图片与文字**：双击聊天图片打开独立看图窗口，可连续浏览会话图片并离线识别文字。
6. **任务**：左侧「任务」页签管理项目与任务；截止提醒与共享见上文章节。
7. **互动**：私聊右键对方头像扔纸飞机 / 墨弹；PK 菜单邀请角斗场。

## 本地 Agent 编码协作

「Agent」页会扫描本机 PATH 与常见安装目录，并把手动指定的 ACP 可执行文件加入列表。首次打开且没有扫描记录时会自动扫描一次。Windows 上每次扫描都会重新读取注册表中的用户 / 系统 PATH，因此在阳鸽启动之后才安装或升级的 CLI 也无需重启即可被发现；握手按固定并发上限执行，冷启动较慢的机器不会因为一次拉起全部 CLI 而误报失败。基础 CLI 与可连接的 ACP Agent 分开显示：Codex CLI、Claude Code、Pi、OpenCode、Gemini CLI、GitHub Copilot 等如果只有基础命令，会提示所需适配器；只有 ACP 握手成功的实现才能创建会话。扫描失败时会显示失败的可执行文件名与错误原因；装在自定义目录的 CLI 可用「添加 ACP 可执行文件…」手动指定。阳鸽不会自动安装、登录或下载 Agent。

每个 Agent 都可设置显示名称、简介、角色提示词、模型和启用状态。显示名称、简介与启用状态只保存在本机；角色提示词会随单聊输入或协作步骤发送给该 CLI 配置的模型供应商。提示词不会授予工具权限，也不构成操作系统沙箱。

协作任务只处理 Git 项目中的编码工作。用户指定协调者和至少包含实现者、审查者的团队，协调者必须先产出 1–5 步计划，用户确认后才执行。同一时刻只有一个实现 Agent 写入专用 worktree，实现与审查必须由不同 Agent 完成，最多两轮审查；最终步骤完成后，用户查看文件列表和 diff，明确确认后才应用到源仓库工作区。阳鸽不会自动 commit、merge 或 push。

源仓库必须干净且不能处于 detached HEAD。创建任务时从当前 `HEAD` 建立独立分支和 worktree；应用前再次检查源分支与基础提交。Git worktree 只隔离代码工作区，不是操作系统沙箱，Agent 进程仍拥有其自身权限。

工具权限默认逐次请求，用户可对本会话授权；超时、取消或关闭会话都按拒绝收口。重启后以已保存的任务、步骤和事件为准，中断步骤会使用新的 ACP 会话重试。任务记录和最终 diff 保存在本机。Agent 模型请求可能连同任务上下文发送给该 CLI 自己配置的云端供应商；阳鸽不保存这些凭据。

## 工作原理

每个客户端都是平等的对等节点（P2P），整个系统**不设立中心服务器**：

```text
渲染进程 (Renderer) —— 会话列表 / 聊天面板 / 共享文件柜 / 任务与角斗场 / 设置窗口
   │  仅通过 contextBridge 暴露的安全 IPC 契约通信
主进程 (Main)
   ├─ 网络服务 (Net)   : UDP 广播发现与心跳、UDP+ACK / TCP 消息通道、TCP 文件直传
   ├─ 业务服务 (Services): 联系人、群组、文件柜、任务、角斗场、离线队列、Agent 协作
   ├─ 存储层   (Store) : SQLite（WAL + FTS 全文索引，持久化消息、群组、授权与传输记录）
   └─ 系统集成 (System): 托盘、通知、全局快捷键、内置 OCR 调度与窗口管理
```

| 通道 / 模块 | 传输方式 | 默认端口 | 主要用途 |
|---|---|---|---|
| 节点发现 | UDP 广播 / 单播 | 17878 | 上线广播、在线应答、心跳保活、离线通知与共享网段交换 |
| 控制与短消息 | UDP + ACK 重传 | 17878 | 文本、送达回执、撤回、窗口震动、群控制、任务与角斗场控制帧 |
| 长文本通道 | TCP 直连 | 17879 | 超过 UDP MTU 的超长文本回退 |
| 文件与数据传输 | TCP 直连 | 17879 | 文件 / 文件夹分块校验直传、文件柜上下行、P2P 更新包拉取 |

节点发现参考 IP Messenger 的上线广播与应答思想，通信协议采用自主设计的 UTF-8 JSON 格式，独立于传统 ipmsg 协议。

## 安全性

- **网络边界明确**：所有通信限制在局域网；启动时全局追加 `--no-proxy-server` 阻断代理；应用内零外部请求、零数据上报、零自动检查更新。
- **最小化攻击面**：渲染进程仅加载本地打包资源；强制 `contextIsolation` 与 Chromium 沙箱，禁用 `nodeIntegration`；拦截页面跳转与新窗口；严格 CSP。
- **不可信输入防护**：所有网络报文执行格式与长度白名单校验；未知类型平滑忽略；内联图片限制单边 ≤8192px 且总像素 ≤3200 万。
- **本地落盘防护**：接收文件名执行路径穿越清洗；保存严格落在用户目录或隔离子目录；重名自动编号；文件柜上传只写指定子目录。
- **日志脱敏**：消息正文与文件内容不写入日志，仅记录消息 ID、状态码、文件体积等审计元数据。
- **物理内网信任模型**：沿用 IP Messenger / iptux 的局域网明文传输模型，适合边界受控的内网、隔离办公区或专用实验室。

## 诊断与反馈

遇到问题后，打开 **设置 → 关于 → 诊断与反馈 → 导出诊断包**，选择保存位置，再手动把 ZIP 附到 Issue。「复制环境信息」可补充问题描述。请注明发生时间、操作步骤和预期结果；文件 / 图片传输问题建议双方分别导出，并标明发送端、接收端。

诊断包包含版本、系统 / 架构、监听与权限状态、近期运行记录。日志最多保留 **7 天、10 MiB**，不记录聊天正文、文件名 / 内容、屏幕画面、剪贴板内容、凭据或原始错误正文。默认匿名化节点与网络地址；「附带真实网络地址」默认关闭。复制环境信息始终脱敏，应用不会自动上传或连接外网。

| 平台 | 默认日志目录 |
|---|---|
| Windows | `%APPDATA%\阳鸽\logs` |
| Linux / UOS / 麒麟 | `${XDG_CONFIG_HOME:-~/.config}/阳鸽/logs` |
| macOS | `~/Library/Application Support/阳鸽/logs` |

开发实例覆盖 `PANTRY_USER_DATA` 时使用该目录的 `logs` 子目录。目录不可写时仅保留受限内存记录；退出后内存记录无法恢复。

## 参与开发

想自己编译、修改代码，或在本机多实例联调，请参阅 **[CONTRIBUTING.md](CONTRIBUTING.md)**；整体架构、模块分层与扩展点见 **[DEVELOPMENT.md](DEVELOPMENT.md)**。

常用命令：

```bash
npm install            # 安装依赖并重建 better-sqlite3
npm run dev            # 开发模式
npm test               # 164 个测试文件 / 1247 项测试
npm run typecheck      # 主进程 + 渲染层类型检查
npm run test:db        # 数据库迁移与自测
npm run build          # 构建 renderer / preload / main
npm run dist:win       # 生成 Windows 安装包与便携版
```

**界面语言**：设置 → 通用 → 语言 / Language，简体中文 / English 即时切换。

完整文档索引见 **[docs/README.md](docs/README.md)**；英文规范见 **[docs/en/](docs/en/)**。
